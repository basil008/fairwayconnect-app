## ⚠️ REQUIRED BEFORE DEPLOYING

1. **Set the session secret** (auth will refuse to start in production without it):
   ```
   fly secrets set SESSION_SECRET=$(openssl rand -hex 32) -a fairwayconnect-live
   ```
2. **Run migrations against Turso** (adds member_id to deductions, formalises columns):
   ```
   DATABASE_URL=libsql://... DATABASE_AUTH_TOKEN=... npm run migrate
   ```
3. **Rotate ALL PINs after deploy** — the old ones shipped in repo database files
   and must be treated as compromised:
   ```
   fly ssh console -a fairwayconnect-live
   npx tsx scripts/rotate-pins.ts --members --admin <new-admin-pin>
   ```
   (Prints a member→PIN sheet for the secretary; distribute securely.)
4. Optional, for the Mac Mini / OpenClaw automation:
   ```
   fly secrets set MACHINE_API_TOKEN=$(openssl rand -hex 24)
   ```
   The bot then sends `x-api-token: <token>` for admin-level API access.

## Stage 1 — Security (P0)

### Server-side authorisation (new)
- `src/middleware.ts` — every `/admin/**` page and every mutating API route now
  requires a **signed HttpOnly session cookie** verified server-side. Admin-only
  route list covers finalise, resets, recalcs, member/event/course writes,
  deductions, imports, captain's prize, scan-scorecard. Default-deny: any other
  write requires at least a member session.
- `src/lib/session.ts` — HMAC-SHA256 tokens (Web Crypto; works in both Edge
  middleware and Node routes). Admin sessions 8h, member sessions 30 days.
- `src/lib/rateLimit.ts` — sliding-window limiter. Admin login: 5/15min/IP.
  Member login: 10/15min/IP. (In-memory; single-machine deployment.)

### Credential leaks closed
- `GET /api/admin/settings` **no longer returns `admin_pin`** — to anyone,
  including admins (write-only key), and the whole route now requires an
  admin session anyway.
- New `GET /api/settings/public` with an allowlist of safe keys; the member
  scoring page now uses this instead of the admin endpoint.
- `GET /api/members` returns only `id, name, handicap, member_type, status,
  handicap_updated_at` publicly. Emails, phones, and PINs are returned **only**
  to an admin session (needed for PIN distribution).
- Member PIN login moved from `GET /api/member-pin/[pin]` (PIN in the URL →
  logs, history, proxies) to **`POST /api/auth/member-login`** with the PIN in
  the body. New `/api/auth/session` and `/api/auth/logout` endpoints.
- Admin login no longer falls back to a default PIN; unset = login disabled.
- `update-handicap` derives the member from the **session**, not the request
  body — members can no longer edit each other's handicaps. Admins may still
  act on behalf of a member.

### Attack surface removed (23 routes deleted)
- Destructive: `recreate-schema` (dropped all tables!), `import`,
  `direct-import`, `complete-import`, `import-missing`, `import-scores`
- One-off data surgery: `fix-terry-scorecard`, `fix-tommy-doyle-rsvp`,
  `fix-ashbourne`, `fix-ashbourne-whs`, `fix-rsvp-data`, `fix-tables`,
  `add-ashbourne-metadata`
- Debug: `debug/admin-data`, `test-db`, `test-twos`, `members-simple`
- Runtime schema mutation: all 5 `migrate-*` routes, plus the ALTER TABLE
  that ran inside the login handler
- `recreate-schema` survives as a CLI script (`scripts/recreate-schema.ts`)
  that refuses to run without `--yes`.

### Data shipping fixed
- `Dockerfile` no longer copies `database/` into the image; `.dockerignore`
  excludes all `*.db` files and `data/`. **The 38 real member records, 34
  plaintext PINs, and the admin PIN no longer ship with every deploy.**
- `scripts/rotate-pins.ts` added for the mandatory post-deploy rotation.

### Client updates
- `PinGate`, `MemberPickerBanner` → POST login endpoint.
- `AdminAuth` hook and admin login page → cookie session via `/api/auth/session`
  (the sessionStorage flag is gone; the server middleware is the real gate).
- Logout actually clears the server session.

## Stage 2 — Integrity (P1)

### One database driver everywhere
- `src/lib/db.ts` rewritten: **libSQL client for both local (`file:`) and
  production (Turso)**. The better-sqlite3 compat layer — with its regex-based
  read/write detection and missing batch support — is deleted, along with the
  `better-sqlite3` dependency and the dead `seed.ts` placeholders (imported by
  12 routes, all no-ops).
- New `executeBatch()` for atomic multi-statement writes.
- `LOCAL_DB_PATH` env override supported (used by the test suites).

### Transactional finalise
- `POST /api/finalise` now collects **all** writes (prize delete + inserts,
  Twos regeneration, GOTY rows, deduction updates, audit log, event status)
  and commits them in a **single atomic batch**. A mid-finalise failure leaves
  the event exactly as it was. This was proven live during testing: a schema
  mismatch aborted the batch and the original published prizes survived intact —
  under the old code that failure mode deleted the prizes first.
- Deduction bookkeeping for winner detection now uses an in-memory allocation
  list instead of re-reading half-written DB state.

### Deductions keyed by member_id
- Migration `006` adds `member_deductions.member_id`, backfills by the old
  name rule once, and indexes `(member_id, year)`. 36/59 historical rows
  matched; the 23 unmatched are ex-members not in the members table (verified).
- Finalise reads and writes deductions by `member_id` (name lookup retained
  only for legacy rows). New rows always carry `member_id`. The two-Keenans
  surname-collision hazard is closed.
- `outing_N` column names clamped to integers 1–8 in finalise/revert/reset.

### One Stableford implementation
- The member scoring page's private copy (plain `Math.round(index)`, no slope,
  no allowance) is **deleted**; it now imports the shared WHS-corrected
  `calculateStablefordPoints` and receives the event's course settings, so
  on-course points match the server exactly.
- The scorecards **PUT recalc** path was also missing course settings — fixed.
  Note: running recalc on pre-fix events will adjust stored points (observed:
  +3 across 28 cards on Event 1) — that is the July WHS fix being applied, and
  the recalc is verified idempotent thereafter.

### Migration system
- `scripts/migrate.ts` + `schema_migrations` table; `npm run migrate`.
- Existing migrations renumbered 001–004; new: 005 (member tracking columns,
  formerly runtime ALTERs), 006 (deductions member_id), 007 (tables missing
  from older local DBs: goty_points, player_event_stats, pricing_items,
  season_standings), 008 (activity_log.event_id).
- Runner tolerates duplicate-column errors so it is safe on databases where
  the old runtime ALTERs already ran (i.e. production).

### TypeScript strictness restored
- `ignoreBuildErrors: true` **removed** from next.config.ts. The 56 hidden
  type errors it was suppressing are all fixed (a syntax error in generated
  code had been masking most of them from `tsc`). `npx tsc --noEmit` is clean
  and `next build` passes with checking enabled.

### Tests (new)
- `tests/stableford.test.ts` — 11 tests: WHS playing handicap incl. an explicit
  regression test that the allowance is applied **before** rounding, stroke
  allocation by SI, the full points ladder, and client/server parity.
- `tests/countback.test.ts` — 6 tests: back 9 → back 6 → gross ordering,
  antisymmetry, ties, 9-hole slices.
- `scripts/test-stage1.sh` — 36 live-server security assertions.
- `scripts/test-stage2.sh` — 14 integration assertions including a
  **golden-master re-finalise** of the real Event 1: overall podium and Back 9
  reproduce the originally published results exactly; Front 9 and Twos are
  verified against independent recomputation from raw hole scores (the new
  engine corrects two historical allocation errors — see below).

## Behavioural corrections surfaced by testing (for the committee's awareness)

Re-running finalise on Event 1 with the corrected engine differs from the
originally published prizes in two places, both verified against raw data:

1. **Two Twos were never awarded**: Tom Scully (hole 6) and Joe Ryan (hole 17)
   both have a gross 2 in the stored hole scores.
2. **Front 9**: Brian Keenan and Ray Daly tie on 17 adjusted points; the ALGS
   countback (lower gross on the 9-hole slice) gives it to **Ray Daly, 45 vs 46**.
   The published result shows Keenan.

Whether to retrospectively amend published results is a committee decision —
the engine now applies the documented rules consistently either way.

## v3 addendum (3 July 2026) — Alpine/native-binding fix
- ROOT CAUSE of the all-endpoints-500 failure: v2's `db.ts` statically imported the
  `@libsql/client` NODE entry, which loads the `libsql` native binding at module
  scope; Next standalone tracing does not ship @libsql/linux-x64-musl to the Alpine
  container, so every route crashed on import. (v107 worked because it used
  `@libsql/client/web` — pure fetch, no native code.)
- FIX (db.ts only; nothing else changed): type-only static imports; remote Turso
  URLs use the WEB client (zero native code); the node client is dynamically
  imported solely for local file: databases on the Mac Mini.
- VERIFIED by running the actual standalone server.js with ALL native libsql
  packages deleted from node_modules (exact Alpine condition): requests reach
  Turso over HTTP; zero module errors. Plus full re-run: 17+36+14 tests,
  preflight 10/10, tsc clean.
- Preflight now permanently checks for module-scope @libsql value imports.
